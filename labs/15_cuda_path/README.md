# Путь одной CUDA-инструкции

Лабораторная к главе 15 «Устройство GPU»: разделы 15.2 «Компиляция ядра CUDA» (`axpy.cu`) и
15.5 «Давление на регистры и занятость» (`register_pressure.cu`). Нужны карта NVIDIA и набор CUDA
(`nvcc`, `cuobjdump`, `ncu`); команды ниже выполняются из каталога `labs/15_cuda_path`.

Лаборатория отделяет четыре свидетельства: исходный код, PTX, машинный код и профиль реального запуска.
Числа регистров и имена машинных инструкций зависят от версии набора CUDA и архитектуры GPU, поэтому они
не зафиксированы в README как «правильный ответ».

## 1. Одно вычисление

```bash
nvcc -O3 -lineinfo --ptxas-options=-v axpy.cu -o axpy
nvcc -O3 -lineinfo -ptx axpy.cu -o axpy.ptx
cuobjdump --dump-sass ./axpy > axpy.sass
./axpy
ncu --set full --kernel-name axpy ./axpy
```

Инвариант выполнения: программа печатает `y[0]=10.0`. В PTX и машинном коде нужно найти не одинаковые
строки, а одинаковые роли: вычисление адреса, проверку границы, две загрузки, умножение-сложение и сохранение.

## 2. Давление на регистры

```bash
nvcc -O3 -lineinfo --ptxas-options=-v register_pressure.cu -o register_pressure
./register_pressure
ncu --set full --kernel-name one_accumulator ./register_pressure
ncu --set full --kernel-name eight_accumulators ./register_pressure
```

Перед запуском запишите прогноз: вариант с восемью одновременно живыми накопителями должен потребовать не
меньше регистрового состояния. Время нельзя интерпретировать отдельно от числа инструкций, активных групп и
проливов. Вариант с восемью накопителями также имеет восемь независимых цепочек зависимостей: это необходимо,
чтобы накопители оставались живыми, и одновременно меняет доступный параллелизм инструкций. Поэтому опыт
проверяет причинную цепочку «исходный код → регистры и инструкции → выполнение», а
не влияние одного изолированного параметра. Разные компиляторы вправе преобразовать исходный код по-разному;
это часть опыта, а не ошибка книги.

## 3. Контролируемое ограничение

Повторите сборку с несколькими значениями `--maxrregcount`. Для каждого сохраните:

- команду и версию `nvcc`;
- название GPU и вычислительную возможность;
- регистры на поток и локальную память из отчёта `ptxas`;
- активные группы и причины остановок из профиля;
- среднее время после прогрева;
- проверку численного результата.

Цель — найти не минимальное число регистров, а причинную границу: дополнительная активная группа перестаёт
окупать добавленные загрузки, сохранения или инструкции.
